# 设计说明

**权限。** `library/api.py` 从 Bearer Token 取得馆别、用户和角色，用馆别及用户 ID 约束任务和引用查询。`library/core.py` 和 `library/books.py` 在证据进入模型网关前约束馆别和可见范围，`library/gateway.py` 只采纳落在本次证据集合内的引用。接入向量索引时，每个资料片段和派生产物继承馆别与受众。在向量候选检索时施加同样过滤，在原文读取与模型出站前再次验证。

**恢复。** PostgreSQL 唯一约束保证同用户幂等键只建一个任务。API 完成受理事务后返回 202。Worker 用会话级 advisory lock 保证单实例消费，领取事务、记录模型尝试、提交结果分别独立，网络调用在事务外。成功后在同一事务提交尝试结果、答案和用量。重启先读未完成尝试的收据。mock 返回 404 时，等待其最长已知执行时间后复查，仍缺失则沿用原尝试 ID 重发。重发如返回 409 则再查收据。收据查询不可用时结束任务。真实模型结果无法核实时保留失败状态。业务只计入最终采纳的成功调用，供应商可能另行计费。需要多个消费组、长时间保留可重放事件，或单库事务成为瓶颈时再考虑 Kafka。只有出现高频共享缓存或限流状态需要时才考虑 Redis。

**发布。** Kubernetes 将 API 和 Worker 分为两个 Deployment。API 使用 `/healthz` 就绪探针，Worker 保留单副本和数据库锁。挂载持久化文件存储，模型密钥由 Secret 注入。CI 在每次提交跑本地 mock 的降级、上传及进程退出恢复检查，构建带提交 SHA 的镜像。发布先运行向后兼容的数据库迁移，再更新镜像，回滚时切回上一镜像。监测最早排队任务等待时长，以及按模型和结果分类的调用失败率。
